# Информационные технологии

## Информация и данные

> **Информация** - это сведения, сообщения или данные независимо от формы их
> представления.

Например: у студента Иванова оценка 5. Это информация, она может существовать как
угодно.

```plaintext
преподаватель сказал: "У Иванова 5"

бумага:
Иванов — 5

JSON:
{
    "student": "Иванов",
    "grade": 5
}

SQL:
student_id | grade
-----------+------
42         | 5
```

Смысл во всех случаях один.

> **Данные** - это информация, представленная в виде, пригодном для обработки
> автоматическими средствами при возможном участии человека.

То есть когда мы представили информацию в формализованном виде, то компьютер уже
может с ней работать:

```json
{
  "studentId": 42,
  "grade": 5
}
```

Отсюда полезная программистская модель:

```plaintext
ИНФОРМАЦИЯ
"У Иванова оценка 5"
        │
        │ представляем в формализованном виде
        ▼
ДАННЫЕ
{ student_id: 42, grade: 5 }
        │
        │ автоматическая обработка
        ▼
ДАННЫЕ
{ average_grade: 4.7 }
        │
        │ представляем результат человеку
        ▼
ИНФОРМАЦИЯ
"Средняя оценка Иванова — 4,7"
```

Информация представляется в виде данных, пригодных для автоматизированной
обработки. Программа обрабатывает эти данные и получает новые данные, которые
затем могут быть представлены и интерпретированы человеком как информация.

> Ключевое: все данные являются информацией, но не вся информация является данными.

```plaintext
┌────────────── ИНФОРМАЦИЯ ──────────────┐
│                                        │
│   "Сегодня холодно"                    │
│                                        │
│       ┌────── ДАННЫЕ ───────┐          │
│       │ temperature = -5    │          │
│       │ user_id = 123       │          │
│       │ grade = 5           │          │
│       └─────────────────────┘          │
│                                        │
└────────────────────────────────────────┘
```

## Информатика

> **Информатика** изучает процессы работы с информацией и средства, позволяющие эти
> процессы реализовать.

Причем явно выделяются следующие процессы:

- **получение**;
- **обработка**;
- **хранение**;
- **передача**;
- **представление**.

Например, backend практически постоянно занимается именно этим:

```plaintext
HTTP request
     ↓
 получение

JSON → struct
     ↓
 обработка

INSERT INTO ...
     ↓
 хранение

HTTP response
     ↓
 передача

UI
     ↓
 представление
```

## Информационная технология

**Информационная технология** - это _процессы_ и методы:

- поиска;
- сбора;
- хранения;
- обработки;
- предоставления;
- распространения.

информации, а также способы осуществления этих процессов и методов.

То есть информационная технология отвечает на вопрос:

`Как мы работаем с информацией?`

Например:

```plaintext
получили данные пользователя
        ↓
проверили
        ↓
сохранили
        ↓
обработали
        ↓
предоставили другому пользователю
```

Это информационная технология.

## Информатизация

**Информатизация** - это внедрение и развитие работы с информацией с использованием
современных информационных ресурсов и технологий.

Допустим, университет раньше работал так:

```plaintext
Бумажное расписание
Excel
Бумажные заявления
Журналы преподавателей
```

А потом появляется:

```plaintext
        Информационная система

Студенты ─────┐
              │
Преподаватели ├──→ единая система
              │        │
Деканат ──────┘        ├── расписание
                       ├── оценки
                       ├── заявления
                       └── отчётность
```

Переход университета к такой работе можно рассматривать как информатизацию.

## Информационная система

> **Информационная система** - это совокупность содержащейся в базах данных информации
> и обеспечивающих ее обработку информационных технологий и технических средств.

```plaintext
                    ИНФОРМАЦИОННАЯ СИСТЕМА
                              │
     ┌──────────┬─────────────┼─────────────┬──────────┬─────────────┐
     ▼          ▼             ▼             ▼          ▼             ▼
  Данные       ИТ            ПО        Технические  Персонал   Документация
                                          средства
```

Здесь появляется важное различие:

**Информационная технология** - это процессы и методы работы с информацией.
**Информационная система** - это система, в которой эти технологии применяются к
данным с использованием соответствующих средств.

Тогда состав информационной системы имеет вид:

- **Данные** — информация, представленная в виде, пригодном для автоматизированной обработки.
- **Информационная технология (ИТ)** — процессы и методы поиска, сбора, хранения, обработки, предоставления и распространения информации.
- **Программное обеспечение (ПО)** — программы, реализующие информационную технологию.
- **Технические средства** — вычислительная техника и другие технические средства.
- **Персонал** — люди, участвующие в работе информационной системы.
- **Документация** — документы, описывающие устройство, эксплуатацию и правила работы системы.

### Современное представление об ИС

> В практической разработке **информационная система != отдельная программа**.

Например, ИС университета может включать:

```plaintext
                    ИНФОРМАЦИОННАЯ СИСТЕМА
                              │
          ┌───────────────────┼───────────────────┐
          ▼                   ▼                   ▼
       Веб-сайт              LMS              Расписание
          │                   │                   │
          └───────────────────┼───────────────────┘
                              │
                             API
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
             БД         Файловое хранилище   Внешние ИС
```

Все эти компоненты могут участвовать в обработке одной и той же информации.
Поэтому полезно разделять понятия **приложение** и **информационная система**.

> **Приложение** - это конкретное программное средство, выполняющее определенные
> функции.

> **Информационная система** - более широкое понятие. Она организует работу с
> информацией и может включать несколько приложений, хранилищ данных,
> технических средства, пользователей и каналов связи.

Поэтому:

```plaintext
Приложение ≠ обязательно вся ИС

ИС
│
├── приложения
├── данные
├── инфраструктура
├── пользователи
├── каналы связи
├── внешние системы
└── правила работы
```

Например, _frontend_ и _backend_ сами по себе являются программным обеспечением.
Вместе с базой данных, инфраструктурой, пользователями и установленными
процессами они могут являться компонентами информационной системы.

### Границы ИС

При проектировании ИС появляется важное понятие - **граница системы**.
Необходимо определить, что относится к проектируемой системе, а что за ее пределами. Например:

```plaintext
                   ВНЕШНЯЯ СРЕДА

       Студент                     Внешняя ИС
          │                            │
          │                            │
 ┌────────┼────────────────────────────┼────────┐
 │        │    ИНФОРМАЦИОННАЯ СИСТЕМА  │        │
 │        ▼                            ▼        │
 │     Frontend ───────→ Backend ←── API        │
 │                         │                    │
 │                  ┌──────┴──────┐             │
 │                  ▼             ▼             │
 │                 БД          Storage          │
 │                                              │
 └──────────────────────────────────────────────┘
```

Студент взаимодействует с системой, но сам может находиться за ее границей.
Внешняя ИС также не принадлежит нашей системе, хотя наша система с ней
обменивается данными. А вот backend, БД и файловое хранилище в данном примере
находятся внутри рассматриваемой границы.

Граница зависит от того, **что именно мы проектируем**. Если проектируется весь
университетский цифровой комплекс:

```plaintext
LMS
Расписание
Электронный деканат
```

То данные компоненты могут рассматриваться как части одной большой ИС. Если
проектируется только LMS, то электронный деканат уже может быть для нее внешней
системой.

> При проектировании **защищенной ИС** граница приобретает дополнительное
> значение: необходимо понимать, **где находятся защищаемые ресурсы и через
> какие точки с ними взаимодействует внешняя среда**.

Представим систему:

```plaintext
                         Интернет
                             │
                             ▼
                        Web-приложение
                             │
                    ┌────────┴────────┐
                    ▼                 ▼
                 Backend            API
                    │                 │
                    ▼                 ▼
                   БД             Внешняя ИС
```

Через каждое взаимодействие информация:

- поступает в систему;
- покидает систему;
- передаётся между её компонентами;
- сохраняется;
- изменяется;
- предоставляется пользователю.

Следовательно, при проектировании недостаточно знать только **какие функции
выполняет система**. Необходимо также понимать:

```plaintext
Какая информация существует?
          ↓
Где она находится?
          ↓
Кто с ней работает?
          ↓
Какие компоненты её обрабатывают?
          ↓
Между какими компонентами она передаётся?
          ↓
Где проходит граница системы?
```

И уже после этого появляется возможность рассуждать о ее защите.

### Информационные потоки

> **Информационный поток** можно представить как движение информации между
> субъектами, процессами, компонентами или системами.

Например:

```plaintext
Студент
   │
   │ логин + пароль
   ▼
Backend
   │
   │ запрос
   ▼
База данных
   │
   │ сведения об аккаунте
   ▼
Backend
   │
   │ результат аутентификации
   ▼
Студент
```

Здесь существует сразу несколько потоков информации. Причем одна и та же
информация в течение своего жизненного цикла может находиться в разных состояниях:

```plaintext
                ДАННЫЕ

                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼

    хранятся   передаются  обрабатываются

        │         │         │
        ▼         ▼         ▼

       БД       сеть      память
```

Например, пароль пользователя:

```plaintext
пользователь вводит пароль
            │
            ▼
      данные в браузере
            │
            ▼
       передача по сети
            │
            ▼
      данные на сервере
            │
            ▼
          обработка
            │
            ▼
сравнение с хэшем из БД
```

С точки зрения защищенной ИС важно уже не просто наличие данных, **а весь путь,
который они проходят**.

## Автоматизированная система

**Автоматизированная система** - это система, состоящая из персонала и комплекса
средств автоматизации его деятельности, реализующая информационную технологию
выполнения установленных функций.

Разберем определение по частям:

```plaintext
АВТОМАТИЗИРОВАННАЯ СИСТЕМА
│
├── Персонал
│
└── Комплекс средств автоматизации
         │
         └── реализуют
                │
                ▼
      Информационную технологию
                │
                ▼
      выполнения установленных
              функций
```

Ключевой момент - **персонал является частью автоматизированной системы**.

Например, возьмем электронный деканат. Есть сотрудник деканата:

```plaintext
Сотрудник
    │
    │ вводит данные
    ▼
Frontend
    │
    ▼
Backend
    │
    ▼
СУБД
```

Система автоматизирует часть его деятельности: сотруднику не нужно вручную
считать средний балл, искать бумажную ведомость, составлять отчёт и т.д.

Поэтому:

```plaintext
Персонал
+
Средства автоматизации его деятельности
=
Автоматизированная система
```

## Отличие информационной системы от автоматизированной системы

**Информационная система**:

```plaintext
ИС
│
├── информация в БД
├── информационные технологии
└── технические средства
```

То есть акцент на обработке информации.

**Автоматизированная система**:

```plaintext
АС
│
├── персонал
└── комплекс средств автоматизации
          │
          ▼
    реализует ИТ
          │
          ▼
    для выполнения
    установленных функций
```

То есть акцент на автоматизации деятельности персонала.

```plaintext
ИС → работа с ИНФОРМАЦИЕЙ

АС → автоматизация ДЕЯТЕЛЬНОСТИ персонала
```

## Информационно-телекоммуникационная сеть

**Информационно-телекоммуникационная сеть** - это технологическая система,
предназначенная для передачи по линиям связи информации, доступ к которой
осуществляется с использованием средств вычислительной техники.

Главное назначение такой системы - **передача информации**:

```plaintext
Компьютер A
     │
     │
     │ линия связи
     │
     ▼
Компьютер B

      передача
      информации
```

## Стандартизация

**Стандартизация** - это деятельность по разработке, утверждению, изменению,
отмене, опубликованию и применению документов по стандартизации, направленная на
достижение упорядоченности в отношении объектов стандартизации.

`Центральная мысль стандартизации: стандартизация нужна, чтобы установить единые
правила и требования.`

Например, представим, что каждая команда самостоятельно решает, как рисовать
UML:

```plaintext
Команда A     Команда B     Команда C

   □              ○             <>
   │              =>            ~~~
   ▼              □             []
```

Один разработчик посмотрит на диаграмму другого и не поймет обозначения. Тогда
появляется стандарт:

```plaintext
                 СТАНДАРТ
                    │
        устанавливает общие правила
                    │
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    Команда A   Команда B   Команда C
```

Теперь участники используют одинаковые правила.

## Документ по стандартизации

**Документ по стандартизации** - это документ, устанавливающий общие
характеристики объекта стандартизации, а также правила и общие принципы в
отношении него для добровольного и многократного применения.

Упрощенно:

```plaintext
Стандартизация
     │
     │ деятельность
     ▼
Документы по стандартизации
     │
     │ содержат
     ▼
Правила / характеристики / принципы
```

То есть **стандартизация** - это деятельность, а **документ по стандартизации** - один
из результатов и инструментов этой деятельности.

## Объект стандартизации

**Объект стандартизации** - это то, в отношении чего мы хотим установить общие
правила или характеристики.

Например:

```plaintext
Объект
   │
   ▼
Техническое задание на АС
   │
   │ устанавливаем требования
   ▼
ГОСТ 34.602-2020
```

Свяжем три понятия стандартизации:

```plaintext
                   СТАНДАРТИЗАЦИЯ
                         │
                         │ деятельность
                         ▼
              достижение упорядоченности
                         │
            ┌────────────┴────────────┐
            ▼                         ▼
 ОБЪЕКТ СТАНДАРТИЗАЦИИ      ДОКУМЕНТ ПО СТАНДАРТИЗАЦИИ
            │                         │
      что регулируем            чем устанавливаем
                                      правила
```

```plaintext
Стандартизация              → процесс / деятельность
Объект стандартизации       → ЧТО стандартизируем
Документ по стандартизации  → КАКИЕ правила устанавливаем
```

## Обязательность введения и следования стандартам

Законодательство устанавливает обязательность применения документов по
стандартизации в определенных сферах. Существуют сферы, для которых имеются
стандарты, но юридически их не обязательно соблюдать.

```plaintext
          Существует стандарт
                  │
                  ▼
      ┌───────────────────────┐
      │ Это ещё не означает,  │
      │ что он всегда         │
      │ обязателен            │
      └───────────────────────┘
                  │
                  ▼
    Обязательность определяется
          законодательством
```

```plaintext
Существует стандарт
        │
        ▼
это НЕ значит
"обязательно всегда"
        │
        ▼
Обязательность его применения
определяется требованиями,
действующими в конкретной ситуации
```

## Ключевой принцип разработки стандартов

При разработке национальных стандартов и технических регламентов в качестве
основы следует использовать международные стандарты.

```plaintext
Международный стандарт
        │
        │ используется как основа
        ▼
Национальный стандарт
```

Это необходимо для того, чтобы страны не изобретали полностью несовместимые правила.

`НО международный стандарт может не использоваться как основа, если его
требования не подходят из-за:`

- климатических особенностей;
- географических особенностей;
- технических особенностей;
- технологических особенностей.

То есть при разработке национального стандарта ориентируемся на международный,
если нет объективных причин этого не делать.

## Классификация стандартов

Стандарты классифицируются на:

- международные;
- региональные;
- национальные;
- отраслевые (ведомственные);
- стандарты организаций.

## Виды работ над автоматизированными системами и программным обеспечением

1. _создание_ - работы по разработке ПО, направленные на создание **новой
   системы**, соответствующей заданным требованиям.

Проще говоря: не было системы -> разработали новую систему.

```plaintext
Заказчик
   │
   │ требования
   ▼
Проектирование
   ↓
Разработка
   ↓
Тестирование
   ↓
Новая АС
```

Если организация решила с нуля разработать с нуля электронный деканат - это
создание АС.

2. _развитие_ - это создание новых функциональных подсистем, новой
   функциональности существующей АС, решение новых задач и комплексов задач.

То есть:

```plaintext
Существующая система
        │
        ├── старая функциональность
        │
        └── + новая функциональность
                    │
                    ▼
                 Развитие
```

Например, электронный деканат уже работает, а мы добавили целую подсистему:

```plaintext
Электронный деканат
├── Студенты
├── Оценки
├── Расписание
│
└── + Электронные заявления
```

3. _модификация ПО_ - это **существенные** изменения функциональности АС.

Например, существующий механизм авторизации серьезно переработали и изменили его
функциональность:

```plaintext
Было:

login + password
       ↓
    session


Стало:

login + password
       ↓
      MFA
       ↓
новая модель сессий
```

4. _адаптация и внедрение_ - приспособление готового ПО под бизнес-процессы заказчика.

Например, существует готовая LMS:

```plaintext
             Готовая LMS
                 │
                 ▼
         Новый заказчик
                 │
        его бизнес-процессы
                 │
                 ▼
             Адаптация
                 │
                 ▼
       LMS под заказчика
```

5. _сопровождение в части настройки и модификации_ - **несущественные** изменения
   функциональности АС.

```plaintext
Изменяем существующую систему
            │
       насколько сильно?
            │
     ┌──────┴──────┐
     ▼             ▼
существенно    несущественно
     │             │
     ▼             ▼
Модификация   Сопровождение
```

6. _авторская поддержка_ - это поддержание АС в работоспособном состоянии,
   устранение сбоев и отказов, обработка запросов по технологическому и
   техническому сопровождению и т.д.

Эти работы авторской поддержки выполняются **разработчиком программы или
правообладателем**.

```plaintext
Разработчик / правообладатель
            │
            │ поддерживает
            ▼
      свою систему
            │
            ▼
   Авторская поддержка
```

7. _техническая поддержка_ - это сопровождение ПО, аналогичное авторской
   поддержке, но выполняемое исполнителем, который не является разработчиком
   программы / правообладателем.

```plaintext
                Поддержка системы
                       │
             кто её выполняет?
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
 Разработчик /                Сторонний
 правообладатель              исполнитель
          │                         │
          ▼                         ▼
    Авторская                 Техническая
    поддержка                  поддержка
```
